# NeuroScan AI

NeuroScan AI is an AI-assisted brain-tumour MRI segmentation prototype developed as an Individual Software Project at Charles University under the supervision of Kassem Anis. It combines a 2D U-Net, a 3D U-Net, Grad-CAM explanations, full-volume MRI inference, and an interactive Streamlit interface.

## Live demo

https://neuroscan-ai-isp.streamlit.app

## Features

### 2D workflow

- Upload one grayscale MRI image (`.png`, `.jpg`, or `.jpeg`).
- Generate a binary tumour mask and red segmentation overlay.
- Display a Grad-CAM attention heatmap.
- Export the generated images.

### 3D workflow

- Upload a four-modality MRI volume in `.npz` format.
- Explore every axial slice in the uploaded volume.
- Display FLAIR, T1, T1CE, or T2 while the model uses all four modalities.
- View the predicted mask, overlay, probability map, and an interactive 3D tumour rendering.
- Process complete patient volumes using overlapping model windows.

The 3D U-Net receives `4 × 32 × 160 × 160` windows. A complete patient volume may contain about 155 slices at `240 × 240`. The app moves through the full depth with overlapping 32-slice windows, predicts each window, restores it to the original resolution, and averages overlapping predictions into one full-volume mask. Therefore, the final result covers all uploaded slices even though the network processes 32 slices at a time.

## Ground truth

Ground truth is not generated by the model. It is displayed only when the uploaded `.npz` already contains a compatible `mask` array with shape `[D, H, W]`. The included labelled BraTS demonstration samples contain ground-truth masks. A normal user upload may contain only the MRI image, in which case the app shows prediction outputs without a ground-truth panel.

## Datasets

### BRISC 2025 — 2D

Used for single-slice brain MRI segmentation:

https://www.kaggle.com/datasets/briscdataset/brisc2025/

Expected local folders:

```text
Data/segmentation_task/train/images
Data/segmentation_task/train/masks
Data/segmentation_task/test/images
Data/segmentation_task/test/masks
```

### BraTS 2021 Task 1 — 3D

Used for multi-modal 3D brain-tumour segmentation:

https://www.kaggle.com/datasets/dschettler8845/brats-2021-task1

The conversion script creates H5 slices at:

```text
archive/BraTS2021_h5/content/data
```

Each H5 file contains:

```text
image  # [H, W, 4]
mask   # [H, W] binary whole-tumour mask
```

MRI channel order:

```text
0 = FLAIR
1 = T1
2 = T1CE
3 = T2
```

All non-zero BraTS tumour labels are combined into one binary whole-tumour target.

The full datasets are intentionally excluded from GitHub because of their size. Only small public demonstration samples are included.

## Saved results

### 2D model

- Best validation Dice: `0.8473`
- Mean IoU: `0.7378`
- Precision: `0.8378`
- Recall: `0.8607`
- Selected threshold: `0.30`

### 3D model

- Best validation Dice after threshold tuning: `0.9326`
- Mean IoU: `0.8737`
- Precision: `0.9368`
- Recall: `0.9284`
- Selected threshold: `0.55`
- Best checkpoint epoch: `35`
- Patient-level split: `1001` training and `250` validation patients

The 3D result is an internal binary whole-tumour evaluation using a patient-level split and full-depth overlapping validation windows. It is not an official hidden BraTS challenge test score.

The five website samples are curated demonstration cases. Their individual results should not be interpreted as average model performance; the validation metrics above are the main reported evaluation.

## NPZ input format

Accepted MRI layouts:

```text
image: [4, D, H, W]
image: [D, H, W, 4]
image: [D, H, W]      # repeated to four channels for compatibility
```

Optional fields:

```text
mask:      [D, H, W]
volume_id: scalar/string
```

## Install and run

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run ui.py
```

## Convert BraTS 2021

Edit `INPUT_ROOT` in `convert_brats2021_to_h5.py`, then run:

```bash
python3 convert_brats2021_to_h5.py
```

The converter preserves zero-valued background and stores the modalities in the documented order.

## Train

2D:

```bash
python3 train.py
```

3D on a selected server GPU, for example physical GPU 1:

```bash
CUDA_VISIBLE_DEVICES=1 python3 -u train_3d.py 2>&1 | tee train_3d.log
```

The 3D pipeline uses:

- patient-level train/validation splitting
- several windows per training patient
- tumour-focused and random context windows
- per-modality normalisation
- mixed-precision CUDA training
- Dice plus weighted BCE loss
- learning-rate reduction and early stopping
- complete-depth overlapping validation
- validation threshold tuning

The app expects the deployed weights at:

```text
best_model/best_unet.pth
best_model_3d/best_unet3d.pth
```

## Verify the repository

```bash
python3 tools/verify_project.py
```

This checks imports, saved metric/history files, model paths, and the existing 2D/3D public samples. It does not modify any files.

## Limitations

- This is an academic prototype, not a medical device.
- It must not be used for diagnosis or clinical decision-making.
- The 3D task is binary whole-tumour segmentation rather than separate BraTS subregions.
- Performance has not been externally validated on an independent clinical cohort.
